------------------------------
Foodgram — Продуктовый помощник 🍲

**Foodgram** — это онлайн-сервис и замена бумажным спискам покупок. Здесь пользователи могут публиковать свои рецепты, подписываться на авторов, добавлять понравившиеся блюда в «Избранное», а перед походом в магазин скачивать сводный список всех необходимых ингредиентов.
Технологический стек

* Python 3.12 / Django 6.0
* Django Rest Framework (DRF)
* PostgreSQL 15
* Nginx & Gunicorn
* Docker & Docker Compose
* Djoser (аутентификация по токенам)

------------------------------
Ключевые особенности реализации

   1. Архитектура на селекторах: Логика получения данных вынесена в selectors.py. Это позволило победить проблему N+1 и оптимизировать запросы к БД через prefetch_related и annotate.
   2. Универсальный импорт: Написана Management-команда для загрузки ингредиентов из CSV с автоматическим запуском через миграции.
   3. Короткие ссылки: Реализован сервис сокращения ссылок на рецепты (/s/ID/).
   4. Безопасность: Настроены кастомные Permissions и защищенный эндпоинт /users/me/.
   5. Docker-контейнеризация: Полностью настроенный стек (Back + Front + DB + Nginx) с автоматическим ожиданием базы (Healthcheck).

------------------------------
Как запустить проект (Локально в Docker)

   1. Клонируйте репозиторий:
   
   `git clone ...`
   `cd foodgram`
   
   2. Настройте переменные окружения:
   Перейдите в /infra .
   Создайте файл .env в папке infra/ (воспользуйтесь шаблоном .env.example).
   
   `cd infra`
   `cp .env.example .env`
   
   3. Запустите сборку контейнеров:
   
   `docker-compose up -d --build`
   
   4. Создайте суперпользователя:

   `docker-compose exec backend python manage.py createsuperuser`

   
   
Проект будет доступен по адресу: http://localhost:8000
------------------------------
API Эндпоинты

* api/users/ — Пользователи (регистрация, профили).
* api/recipes/ — Рецепты (фильтрация по тегам, авторам).
* api/ingredients/ — Справочник ингредиентов.
* api/tags/ — Список тегов (Завтрак, Обед и т.д.).
* api/docs/ — Интерактивная документация (Redoc).

------------------------------
Автоматизация (GitHub Actions)
Проект настроен на CI/CD:

   1. Linting: Проверка кода через Ruff.
   2. Build & Push: Сборка Docker-образов и пуш на Docker Hub.
   3. Deploy: Автоматическое обновление проекта на боевом сервере при каждом git push.
